# 完整调用示例

下面示例展示如何调用 Skill，不绑定具体题材。

```text
使用 novel-outline-worldbuilding Skill，先读取 SKILL.md、AGENTS.md、STATE_CONTRACT.md。

项目暂名：《失效规则修补局》
目标平台：长篇中文网文平台；请先实时确认该平台当前分类与书名规律。
目标字数：220 万字。
目标体验：成长、群像、制度冲突、悬疑真相；总体爽而不无敌。
核心脑洞：世界中的公共规则会像机器一样磨损，只有被官方身份系统遗忘的人能看见裂缝。主角靠修补规则获得资源，却会让既得利益者、受益普通人和旧制度的维护者同时盯上他。

必须保留：
- HC-001：主角不能靠战力解决所有问题。
- HC-002：重要配角彼此必须有独立关系与计划。
- HC-003：规则修补会改变经济、法律与关系，不只是升级。
- HC-004：本阶段只做资料包，不写正文。
- HC-005：至少三轮隔离审计，审一轮改一轮。

绝对禁止：
- 反派集体降智。
- 重要角色卡片化。
- 用无限新地图掩盖重复。
- 模仿任何单一作者的具体风格。

参考作品：
- 作品 A：只研究开篇如何快速建立异常规则。
- 作品 B：只研究群像关系回路。
- 作品 C：只研究卷级真相递进。
不得迁移专名、角色、标志场景、转折顺序和句法。

交付阶段：
1. 建立项目宪法和状态看板。
2. 实时扫榜并给证据。
3. 拆解范例机制并做六层原创性审计。
4. 完成世界、资源、成长、角色、关系、欲望冲突、势力制度。
5. 完成全书卷级总纲、第一卷章级大纲、未来 40 章场景级细纲。
6. 完成标题简介候选、文风声纹手册。
7. 完成三轮以上审计、修订、回归。
8. 全部以 UTF-8 Markdown 落盘，运行验证脚本，交付压缩包。
```

## 协调器首轮应输出

1. 对输入进行 `HC/SP/OH/RQ` 分类。
2. 指出潜在冲突，例如“爽而不无敌”如何兼容。
3. 给出项目文件树和任务依赖。
4. 只提出会阻断工作的待确认问题。
5. 生成 `00_项目宪法.md` 与 `01_总索引与状态看板.md`。

## 不合格响应

- 直接开始写第一章。
- 在未联网时声称“当前榜单流行……”。
- 只给一份大而空的世界观，不建立资源与冲突闭环。
- 用“参考某大神风格”代替声纹参数。
