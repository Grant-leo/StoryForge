# 审计 01｜结构与可执行性

- 审计方式：隔离量表顺序审计；只检查“能否作为 Skill 被执行”，不参考后续审计结论。
- 审计日期：2026-08-24
- 初始结论：conditional pass
- 修订后结论：pass

## 审计问题

1. 用户给出长提示词后，是否有明确的约束冻结、阶段状态和产物门槛？
2. 输出是否能稳定落为 Markdown，而非只在聊天中存在？
3. 是否有可复用模板、代理合同、版本状态和验证工具？
4. 初始化出的项目是否能直接通过基础完整性校验？
5. 压缩交付是否有“先验证后打包”的硬门？

## 发现与修订

### AUD1-001｜P1｜缺少主题层的独立产物

- 发现：原流程覆盖商业、结构、人物和文风，但主题、竞争答案、母题与意象仅分散出现，难以追踪全书价值回收。
- 影响：作品可能“结构完整但没有统一内核”，意象沦为临时修辞。
- 修订：新增 `docs/22_主题母题与意象系统.md` 与 `templates/28_主题母题与意象台账.md`；初始化项目新增 `18_主题母题与意象系统.md`。
- 状态：closed。

### AUD1-002｜P1｜只有验证脚本，没有安全打包门

- 发现：Skill 要求最终交付压缩包，但初版只提供初始化与验证，仍可能人工跳过验证直接压缩。
- 修订：新增 `scripts/package_novel_project.py`，在打包前强制调用验证器，支持 `--final --strict`，排除临时文件与缓存，并执行 ZIP 完整性测试和 SHA-256 输出。
- 状态：closed。

### AUD1-003｜P2｜手动复制模板时元数据可能丢失

- 发现：初始化脚本会自动加前置元数据，但单独复制模板的用户可能忘记添加 `doc_id/status/version`。
- 修订：新增 `templates/README.md`，明确模板是片段，手动使用必须遵循 `STATE_CONTRACT.md`。
- 状态：closed。

### AUD1-004｜P2｜通用模板过多时可能机械填表

- 发现：完整能力包若被当作强制清单，会制造无用设定。
- 修订：新增题材适配与规模裁剪模块，规定 `REQUIRED/OPTIONAL/N/A/DEFERRED` 四种字段状态。
- 状态：closed。

## 回归结果

- 初始化脚本可生成 29 个 Markdown 文件。
- 生成项目的必需文件、前置元数据、H1、代码围栏和本地链接均可校验。
- 候选项目允许占位符并给警告；最终项目使用 `--final` 会阻止未处理占位符交付。
- 打包脚本会在验证失败时停止，不生成 ZIP。

## 剩余风险

内容层的实体交叉引用尚未做到完整语义验证；当前脚本负责结构完整性，人物、事件、规则之间的语义一致性仍需专业审计代理完成。这一边界已在文档中明确。
