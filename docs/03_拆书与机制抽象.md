# 03｜拆书与机制抽象

## 一、拆书的正确单位

拆书不是“第 1 章发生 A，第 2 章发生 B”。真正有用的单位是：

- 承诺。
- 压力。
- 选择。
- 代价。
- 状态迁移。
- 信息释放。
- 关系变化。
- 情绪回报。

因此每个剧情块都应被改写为：

```text
起始状态 → 角色欲望 → 稀缺/阻力 → 策略 → 意外 → 价值选择 → 代价 → 新状态
```

## 二、五层拆解

### 层 1：读者承诺

回答：读者买的究竟是什么体验？

- 身份逆转。
- 破解谜题。
- 建设成长。
- 权力博弈。
- 关系治愈。
- 探索未知。
- 极致战斗。
- 道德困境。

一部作品可有多个，但必须有主次。

### 层 2：结构骨架

按全书、卷、剧情弧、章节、场景分别记录起承转合。重点不是四段名字，而是每一层的“状态差”。

### 层 3：角色发动机

- 主角想要什么。
- 反派为何不能让步。
- 配角如何借冲突实现自己的计划。
- 谁掌握资源、身份、证据或舆论。
- 哪段关系承担连续阅读。

### 层 4：信息与认知

记录：

- 读者知道、主角不知道。
- 主角知道、读者不知道。
- 双方都误以为知道。
- 真相揭露后，旧事件如何被重新解释。

高质量反转通常改变意义，而不只是新增事实。

### 层 5：表达参数

只抽象高层特征：

- 叙事距离。
- 句长与段落节奏。
- 对白/动作/说明比例。
- 幽默、冷峻、诗意或克制的程度。
- 意象类型与使用频率。

禁止摘取独特句式后要求“照这个写”。

## 三、单书拆解的三个视角

### 作者视角

作者如何安排伏笔、遮蔽、回报和升级？

### 角色视角

角色不知道后续，他为何在当时作出那个选择？若只能用“作者需要”解释，结构存在弱点。

### 读者视角

读者为什么继续读？是在等答案、等打脸、等关系确认、等身份暴露，还是等价值选择？等待多久，期间得到什么中间回报？

## 四、拆解后必须进行抽象

示例：

```text
表层：主角在宗门测试中被判为废材，随后隐藏天赋反转。
机制：公共评价系统错误分类 → 主角掌握私有验证方法 → 先承受低估红利 → 在高价值节点重新定价。
抽象原则：让“评价错位”同时产生压迫、隐蔽空间与未来回报。
原创实现：可改为职业许可、算法评级、血统档案、信誉系统等；改变错误原因、受益方式和暴露代价。
```

若抽象后只能得到“主角被看不起后打脸”，说明拆解仍停留在套路标签。

## 六、反例研究

每个成功机制都找至少一个失败用法：

- 同样快节奏，为何一部爽、一部空？
- 同样隐藏实力，为何一部期待感强、一部憋屈？
- 同样多女主，为何一部角色有生命、一部像收集卡？
- 同样宏大世界，为何一部有敬畏、一部只是名词膨胀？

反例能帮助区分“必要条件”和“表面共现”。

## 七、输出格式

每部作品的拆解卡必须包含：

1. 数据来源与阅读范围。
2. 一句话读者承诺。
3. 主角发动机。
4. 关系发动机。
5. 核心规则与稀缺。
6. 全书/卷级状态迁移。
7. 信息释放节奏。
8. 回报周期。
9. 高层文风参数。
10. 可迁移机制。
11. 不可迁移的标志性表达。
12. 对本项目的启发与风险。
